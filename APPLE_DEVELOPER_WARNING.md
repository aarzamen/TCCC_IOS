# ⚠️ APPLE DEVELOPER SIGNING — READ BEFORE TOUCHING BUILD SETTINGS

**Project:** `TCCC_IOS` · **Remote:** https://github.com/aarzamen/TCCC_IOS.git

This file is a sign for AI agents and humans. It is here because this project
carries Apple code-signing configuration. It does **not** change anything in the
project. Do not delete it; do not "fix" the project's signing to match a guess.

This is the **public half** of the warning. The machine-specific half
(team ID, certificate fingerprints, expiry dates, local paths, the per-file
signing scan) is generated by the local apple-developer-kit scripts and belongs
in `APPLE_DEVELOPER_WARNING.local.md`, which is ignored by git. If you
regenerate the warning, write the output there, and keep this file free of
identifiers and paths.

## Where signing identity lives

- `project.yml` sets `CODE_SIGN_STYLE: Automatic` and no team. Both
  configurations read the tracked, identity-free `Config/Signing.xcconfig`,
  which optionally includes `Config/Signing.local.xcconfig`: **untracked**, and
  the only place `DEVELOPMENT_TEAM` is set. Copy
  `Config/Signing.local.xcconfig.example` to create it. Fresh clones and CI
  (`CODE_SIGNING_ALLOWED=NO`) build without the local file.
- `scripts/archive_and_export.sh` reads the team ID from that file or from
  `TCCC_DEVELOPMENT_TEAM`.
- Bundle identifiers: `com.aarzamen.TCCCai` (app), `com.aarzamen.TCCCaiTests`
  (tests), prefix `com.aarzamen`.

## Rules for AI agents

1. The team ID comes from `Config/Signing.local.xcconfig` or the environment, never
   from a literal in a tracked file. The 10-character ID that appears inside an
   `Apple Development: Name (XXXXXXXXXX)` certificate name is a certificate
   user ID, **not** a team ID; using it as `DEVELOPMENT_TEAM` fails with
   "No Account for Team".
2. Do not touch the Apple Developer account: no creating/revoking certificates,
   no registering App IDs, devices, keys, containers, or capabilities, no
   `-allowProvisioningUpdates` / `-allowProvisioningDeviceRegistration`, no
   SideStore/AltStore, without the user's explicit OK in the same session.
3. Build with the profiles that exist. If one is missing or stale, stop and ask
   the user for one automatic-signing build in the Xcode GUI.
4. Secrets (`.p12`, `.p8`, `.mobileprovision`, `.cer`, keychains) never go
   inside this repository. In public repositories the team ID comes from
   env/config, never a literal.
5. XcodeGen projects: `project.yml` is the source of truth; the generated
   `.xcodeproj` is disposable. Regenerate it after changing `project.yml`.
6. Read the local canonical facts (`~/apple-developer-kit/APPLE_DEVELOPER_ACCOUNT.md`,
   outside this repository) and run the local status script before giving
   signing advice.
